## Session-only is the default

Impactful Tom uses the current conversation by default. It does not create a durable founder profile, automatically save a case, infer analytics consent, collect hidden telemetry, or construct a psychological dossier.

If you want continuity, ask for it explicitly and choose the location yourself. The optional portable file is named `founder-case.md`. It is meant to hold business-decision state such as the current decision, mission and market hypotheses, evidence, constraint map, next move, threshold, horizon, and result.

Before accepting a saved case, make sure you can inspect, correct, export, and delete it. Keep sensitive data out unless it is genuinely necessary for the decision.

## Correct and delete a Founder Case

User statements, observed evidence, and model inference should be labeled separately. If an inference is wrong, say so and ask for a visible correction. If you want the file removed, request deletion of the exact location you chose and expect a clear result from the host before treating it as deleted.

If the host cannot write to the location you choose, the safe result is a portable draft in the conversation marked **not saved**. Do not assume a file exists because a useful-looking case was drafted.

## Current claims need current evidence

For a volatile claim—such as a current law, platform rule, price, competitor, capital condition, or regulation—the skill should use current authoritative evidence when that capability is available. Without it, treat the conclusion as provisional and prefer a reversible move or qualified review.

## High-consequence decisions

Do not use the skill as a source of definitive legal, regulatory, investment, tax, medical, clinical, safety, or security advice. It can help you identify the decision, preserve evidence, reduce a risky move, and decide which qualified person needs to review it. It should not invent statutes, deadlines, penalties, procedures, or guarantees when current authority is unavailable.

Requests to hide information, deceive people, exploit a vulnerability, or coerce staff, customers, partners, or investors are outside the method. The constructive alternative is transparent incentives, consent-respecting choices, honest evidence, and bounded experiments.

## External actions need separate authority

The skill can recommend a move. It is not authorized to send messages, publish content, purchase anything, change accounts, delete data, contact third parties, or take another consequential external action unless you separately authorize that exact action in a host that can perform it.

An attempted external action is not a completed action. Ask for the observed result when the difference matters.

For the package-level data statement and host boundary, read [Impactful Tom Data and Privacy](https://github.com/Stunspot/impactful-tom/blob/main/DATA-AND-PRIVACY.md).

## MIND is not bundled

Impactful Tom owns its founder-specific method. A host may provide MIND, Omnicompetence, or another cognition layer, but this package does not install or recreate them. When a host capability is unavailable, the founder method should remain useful without pretending that the missing capability ran.
